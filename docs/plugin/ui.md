# Plugin UI Walkthrough

The plugin view has two top-level tabs: **Library** and **Config**.

## Library Tab

The Library tab is the main interface, with four regions.

### Status Bar

Displays library-wide counters at a glance:

| Counter | Description |
|---|---|
| **Collections** / **Papers** | Total counts |
| **Cached** / **Pending** | Card generation progress |
| **Degraded** | Papers with low-quality PDF extraction |
| **Digests OK** / **Stale** | Digest freshness |
| **BBT live** | Pulsing green dot if BBT JSON was updated within 60 minutes |

### Collection Tree (Left Panel)

A hierarchical tree of all Zotero collections. Each node shows:

- A **colored dot** indicating digest state:
    - **Green** — digest is up-to-date
    - **Amber** — digest exists but membership has changed (stale)
    - **Grey** — no digest generated yet
- The collection name and paper count
- Expand/collapse arrows for subcollections

Click a collection to select it and display its papers in the right panel.

### Paper List (Right Panel)

A table of papers in the selected collection:

| Column | Description |
|---|---|
| **Status** | Icon: checkmark (cached), circle (pending), warning (degraded), dash (no PDF) |
| **Citekey** | BibTeX citation key, with optional paper-type badge |
| **Year** | Publication year |
| **Venue** | Journal or conference |
| **Citations** | Citation count (if available), or `—` |
| **Card** | Badge showing card state |

Review/survey/meta-analysis papers appear in their own group at the top of the list with a `Review Papers (N)` section header.

#### Header Actions

| Icon | Action |
|---|---|
| External link | Open the collection's vault note in Obsidian |
| Refresh | Run `digests --collection` then `redigest --collection` for the selected collection |
| Sort toggle | Switch between year-sorted (default) and citation-sorted order |

Click any paper row to open its note in a popout window.

### Pipeline Controls (Bottom)

Stage buttons map directly to CLI commands:

| Button | CLI Equivalent | Cost |
|---|---|---|
| **Skeleton** | `zsum skeleton` | Free |
| **Cards** | `zsum cards` | LLM tokens |
| **Digests** | `zsum digests` | LLM tokens |
| **Redigest** | `zsum redigest` | LLM tokens |
| **Citations** | `zsum citations` | Free (network) |
| **Publish** | `zsum publish` | Free |
| **Full Run** | `zsum all` | LLM tokens |
| **Reviews** | `zsum reviews` | Free |
| **Restructure** | `zsum restructure` | LLM tokens |
| **Stats** | `zsum stats` | Free |

Below the buttons:

- **Cost estimate** — estimated LLM cost and pending card count
- **Progress bar** — animated bar while a stage is running
- **Log pane** — live, timestamped, color-coded CLI output (auto-scrolls)
- **Cancel** — sends SIGTERM to the running subprocess

## Config Tab

The Config tab edits the external YAML file referenced by plugin settings.

- Fields are grouped by section: Paths, Scope, Extraction, LLM Routing, provider-specific settings, Output, Versioning, Citations, and Restructure
- Dropdowns for finite choices (provider selection, Codex sandbox mode)
- Free-text field for `llm.openai_compat.model`
- Separate provider selectors for `cards`, `digests`, and `redigest` routing
- Explicit save — shows dirty state with **Save**, **Revert**, and **Reload from disk** actions
- YAML writes preserve comments and unrelated keys
- Parse errors disable save and show the error inline

## Data Flow

The plugin reads two files:

1. **Your YAML config** — to resolve paths and display settings
2. **`cache/index.json`** — generated by the CLI, contains all collection and paper metadata

The index is reloaded when the view opens and after each pipeline run completes. There is no filesystem watching or polling — refresh is event-driven.
